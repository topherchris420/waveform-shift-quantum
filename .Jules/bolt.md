## 2026-04-16 - RealitySplitStage Performance and Static Field Re-calculations
**Learning:** In the `RealitySplitStage` component, the `scalar_kernel` mode produces a divergence field that is completely static over time. However, it was being re-calculated on every single frame inside a 60Hz loop (in `draw`) and repeatedly inside a `columns` loop in `computeDivergenceMap`. Redundant computations in hot paths (like a render loop) directly impact performance.
**Action:** When a computed field or state is static based on the application mode (like `scalar_kernel` mode), calculate it once (e.g., using `useMemo` or caching it outside a loop) and reuse the reference rather than re-computing it on every tick or render cycle.
## 2026-04-16 - Spatial Basis Function Re-calculation Overhead
**Learning:** In `computeDivergenceField` during `two_site` mode, the spatial basis functions (`gaussian` distributions for Site A and Site B) were being recalculated for every cell (`gridSize`) on every frame rendering (`60Hz`), even though they depend purely on grid geometry (constant `x`, `SITE_A_X`, `SITE_B_X`, `SITE_WIDTH`). This caused 26,400+ redundant exponential (`Math.exp`) calculations per second per mode instance, needlessly thrashing the CPU in a hot render path.
**Action:** Extract the static, geometry-dependent parts of hot loops into a cache (like `basisCache` for spatial arrays). Calculate them once for a given geometry and reuse the typed arrays (e.g., `Float64Array`) inside the hot path.
