# GPD research workspace

This directory holds **research notes**, not runtime code. Nothing here is imported by the app, the tests or the audit, and nothing here is evidence.

It borrows the methodology of [Get Physics Done](https://github.com/psi-oss/get-physics-done) (GPD): scope a question before computing, lock conventions, derive expected limits before encoding them, check dimensions, limiting cases, symmetries, conservation laws and numerical convergence, and review adversarially. GPD is an agentic research assistant that installs into an AI coding runtime. It is **not** a dependency of Waveform. You install it separately if you want to use it here.

> The division of labour: **GPD proposes and interrogates physics. Waveform deterministically tests it.**

The notes in this directory were written following GPD's workflow and checklists. They were not generated by running GPD's own commands.

## Promotion path

No output of GPD, of any language model, or of a person writing in this directory is authoritative. A claim becomes part of Waveform only by this path:

```
GPD proposal
      ↓
research note            (this directory; may be wrong)
      ↓
formalized claim         (equation, assumptions, expected limit, units)
      ↓
deterministic implementation   (src/, no model decides pass/fail)
      ↓
tests                    (src/test/, including a negative control showing the check can fail)
      ↓
human review             (pull request)
      ↓
Waveform experiment protocol   (versioned; old records keep replaying under old versions)
```

Rules that apply at every step:

1. **Derive before encoding.** A null or limit is written out here first, with the observables that should and should not change. A null is never encoded because it sounds intuitive.
2. **Every declared claim maps to an executed check.** `ResearchModelDescriptor.invariants` and `.limitingCases` name a `checkId`. `npm run physics:audit` fails if any check id is missing.
3. **Metadata can only warn.** A declaration ("g is uncalibrated") is shown as a warning. It never earns a pass.
4. **No invented numbers.** Instrument sensitivities, noise floors and literature values are `unknown` until a real source is cited.
5. **Failures stay.** A failed check is recorded, exported and replayed as failed. It is never tuned away to make a model look better.
6. **Simulation never confirms.** Computational statuses stop at "simulation effect present". Empirical questions stay `empirical_result_required`.

## Running the audit

```bash
npm run physics:audit                # console report + physics-audit.json
npm run physics:audit -- --out x.json
```

The audit is part of `npm run verify` and CI. It exits non-zero only if an executed check fails or a declared claim has no executed check. Warnings (uncalibrated units, identifiability limits, unknown sensitivity) are findings, not failures.
